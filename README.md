# Russian Houses ETL: Airflow + PySpark + ClickHouse

Итоговое задание №8. Пайплайн скачивает CSV с данными о жилых домах России,
анализирует его в PySpark и загружает результат в ClickHouse — всё внутри
одного Airflow DAG.

Кратко: датасет из 590 708 домов (координаты, год постройки, площадь,
регион/город, адрес, описание). Нужно прочитать его в PySpark, проверить и
привести типы, посчитать аналитику (средний/медианный год, топ регионов и
городов, мин/макс площадь по региону, здания по десятилетиям), затем
загрузить обработанные данные в ClickHouse и выполнить SQL-запрос
(топ-25 домов площадью > 60 м²) — всё из Airflow.

## Архитектура

```
Yandex Disk (zip) --> [download_yandex_csv] --> Spark (standalone cluster)
                                                      |
                                                [main.py: read → validate →
                                                 cast types → analytics]
                                                      |
                                                      v
                                              ClickHouse (buildings)
                                                      |
                                          [SQL: top-25 by square > 60]
```

- **Airflow** (CeleryExecutor) оркестрирует DAG `russian_houses_dag` из двух
  тасков:
  1. `download_yandex_csv` (`PythonOperator`) — скачивает архив с Яндекс
     Диска через публичный API, распаковывает вложенный zip, кладёт
     `russian_houses.csv` в `/opt/jobs`. Пропускает скачивание, если файл
     уже на месте.
  2. `submit_spark_job` (`SparkSubmitOperator`) — запускает `jobs/main.py`
     на Spark-кластере.
- **Spark** (standalone: 1 master + 1 worker, 2 cores / 2 GB) читает CSV,
  проверяет и типизирует данные, считает аналитику, пишет результат в
  ClickHouse через `clickhouse-connect`, затем выполняет проверочный SQL
  и печатает топ-25 в лог таска.
- **ClickHouse** хранит таблицу `buildings` (`MergeTree`, `ORDER BY house_id`).

## Почему PySpark, а не pandas

Объём данных (590 тыс. строк, ~330 MB) спокойно поместился бы в pandas.
PySpark использован по условию задания и как демонстрация инструмента,
рассчитанного на кластерную обработку.

## Особенности данных и принятые решения

- **Кодировка UTF-16.** Исходный CSV в UTF-16, а не UTF-8. Чтение построчно
  по умолчанию ломает файл на этой кодировке (перевод строки в UTF-16
  занимает 2 байта, Spark режет файл по одному байту), поэтому используется
  `multiLine=true` + `encoding=UTF-16`.
- **Данные не редактируются (критерий 4).** Мусорные значения (например,
  `maintenance_year = 20082009`, экстремальные `square`) не удаляются и не
  подменяются в таблице ClickHouse. Они отсекаются только в конкретных
  запросах (`WHERE maintenance_year BETWEEN 1700 AND 2026`, `WHERE square <
  1000000`), когда это нужно для конкретного расчёта.
- **Схема ClickHouse.** Таблица `buildings` хранит 6 колонок:
  `house_id, address, region, locality_name, maintenance_year, square`.
  `region`/`locality_name` — `LowCardinality(Nullable(String))` (десятки/
  тысячи уникальных значений), `address` — `Nullable(String)` (почти всегда
  уникален), `maintenance_year` — `Nullable(Int32)` (год может быть
  мусорным и выходить за пределы `UInt16`), `square` — `Nullable(Float64)`.
  Пропуски есть в `region`, `locality_name`, `address`, `maintenance_year`,
  `square` — учтено через `Nullable`.
- **Идемпотентность загрузки.** Перед `insert_df` выполняется `TRUNCATE
  TABLE buildings`, чтобы повторные запуски DAG не удваивали данные.

## Запуск

1. Скопируй `.env.example` в `.env` и задай `CLICKHOUSE_USER` /
   `CLICKHOUSE_PASSWORD`.
2. Подними стек:
   ```bash
   docker compose up -d --build
   ```
3. Создай Airflow Connection `spark_default` — либо через переменную
   `AIRFLOW_CONN_SPARK_DEFAULT` в `docker-compose.yml` (уже настроено),
   либо вручную в Admin → Connections.
4. Создай Airflow Connection `clickhouse_default` (Admin → Connections):
   `Generic`, host `clickhouse`, port `8123`, login/password из `.env`.
5. Открой `http://localhost:8080`, найди DAG `russian_houses_dag` и
   запусти его (Trigger DAG).
6. Результат — топ-25 домов площадью > 60 м² — смотри в логе таска
   `submit_spark_job`. Данные лежат в ClickHouse, таблица `buildings`.

## Известные особенности среды

- **Python 3.8 везде.** Образ `apache/spark:3.5.3-python3` использует
  Python 3.8, поэтому Airflow-образ тоже собран на `apache/airflow:2.9.2-python3.8`
  — иначе driver и executors расходятся по версии.
  По этой же причине `clickhouse-connect` закреплён на версии `0.7.19`
  (более новые версии требуют Python 3.9+).
- **spark-worker может "терять" регистрацию у spark-master** после
  пересборки/перезапуска других контейнеров (UI показывает `Workers (0)`).
  Лечится через `docker compose stop spark-worker && docker compose up -d
  spark-worker`.
- **WSL2 / Docker Desktop**: по умолчанию Docker может получить всего
  ~3.7 GB RAM и 2 CPU, чего Spark + Airflow + ClickHouse не хватает
  (`Cannot allocate memory`). Лимит увеличен через `%USERPROFILE%\.wslconfig`:
  ```
  [wsl2]
  memory=11GB
  processors=4
  ```
